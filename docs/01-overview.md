# 01. Claude Code とは

> **この章でわかること**
> - Claude Code が「チャットAI」と何が違うのか
> - 具体的に何ができるのか
> - どこで動くのか（ターミナル・IDE・デスクトップ・Web など）
> - 使うために必要なアカウント・プラン

---

## 1-1. ひとことで言うと

**Claude Code は「あなたのコードベースを実際に触れる AI エージェント」です。**

チャット版の Claude は、あなたが貼り付けたコードを読んで返答します。
Claude Code は違います。自分でファイルを探し、読み、書き換え、コマンドを実行し、テストを走らせ、失敗すれば直し、最後に git にコミットします。

```
あなた: 「ログイン後に画面が真っ白になるバグを直して」
   ↓
Claude Code:
   1. 関連しそうなファイルを検索する（src/auth/ 配下を発見）
   2. ファイルを読んで原因を推測する
   3. 再現するテストを書く
   4. コードを修正する
   5. テストを実行する → 失敗したら直してもう一度実行
   6. 「直りました。変更点はこれです」と報告する
```

この「自分で調べて、実行して、結果を見て、また動く」というループを **エージェント的ループ（agentic loop）** と呼びます。Claude Code の中心にあるのはこの仕組みです。

### チャット版 Claude との違い

| | チャット版 Claude | Claude Code |
| --- | --- | --- |
| コードの入手方法 | あなたが貼り付ける | 自分でファイルを検索・読み込み |
| コードの変更 | 変更案をテキストで提示 | **実際にファイルを書き換える** |
| コマンド実行 | できない | **ターミナルコマンドを実行できる** |
| 検証 | できない | **テスト・ビルド・Lint を実行して確認できる** |
| Git 操作 | できない | **ブランチ作成・コミット・PR 作成ができる** |
| 得意なこと | 相談、設計の壁打ち、単発のコード生成 | 実際の開発作業そのもの |

## 1-2. 何ができるのか

### よくある使い方

**後回しにしがちな作業を任せる**

```text
auth モジュールのテストを書いて、実行して、失敗したら直して
```

テストが無いコードへのテスト追加、プロジェクト全体の Lint エラー修正、マージコンフリクトの解消、依存パッケージの更新、リリースノートの作成など。

**機能追加とバグ修正**

やりたいことを普通の言葉で説明すれば、Claude Code がアプローチを考え、複数ファイルにまたがってコードを書き、動作を検証します。
バグならエラーメッセージを貼り付けるだけでも構いません。コードベースを辿って原因を特定し、修正します。

**コミットと PR の作成**

```text
変更内容を分かりやすいメッセージでコミットして、PR を作って
```

ステージング、コミットメッセージの作成、ブランチ作成、PR 作成まで会話でこなせます。

**コードベースの理解（オンボーディング）**

新しいプロジェクトに入ったとき、先輩エンジニアに聞くような質問をそのまま投げられます。

```text
ログ出力の仕組みはどうなってる？
新しい API エンドポイントを追加するにはどこを触ればいい？
foo.rs の 134 行目の async move { ... } は何をしてる？
```

**外部ツールとの連携**

MCP（Model Context Protocol）を使うと、Jira のチケットを読む、データベースに問い合わせる、Figma のデザインを参照する、Slack に投稿するといったことができます。詳しくは [08 拡張機能](08-extensions.md) を参照してください。

**スクリプト・CI への組み込み**

Unix ツールのように、パイプで繋いで使えます。

```bash
# ログを流し込んで分析させる
tail -200 app.log | claude -p "異常があれば教えて"

# 変更されたファイルだけセキュリティ観点でレビュー
git diff main --name-only | claude -p "これらのファイルをセキュリティ観点でレビューして"
```

## 1-3. どこで動くのか

Claude Code は複数の「動く場所」を持っていて、公式にはこれを **サーフェス（surface）** と呼びます。
**どのサーフェスでも同じエンジンが動き、`CLAUDE.md`・設定・MCP サーバーの設定は共通で使えます。**

| サーフェス | 概要 | 向いている場面 |
| --- | --- | --- |
| **ターミナル（CLI）** | 最も機能が揃った本体。すべての機能が使える | メインの開発作業。まずはここから |
| **VS Code / Cursor 拡張** | エディタ内で差分表示、`@` メンション、プラン確認 | 変更差分を視覚的に確認しながら進めたいとき |
| **JetBrains プラグイン** | IntelliJ・PyCharm・WebStorm などに対応（CLI が別途必要） | JetBrains 系 IDE がメインの人 |
| **デスクトップアプリ** | 単体アプリ。複数セッションを並べて実行、差分を視覚確認、定期タスク | 複数タスクを並行で回したいとき |
| **Web 版（claude.ai/code）** | ブラウザから。Anthropic 管理のクラウド VM 上で実行 | ローカル環境の準備なしに動かしたい、長時間タスクを投げたい |
| **モバイルアプリ（iOS / Android）** | Web 版のセッションをスマホから確認・操作 | 外出先で進捗確認・指示出し |
| **Slack** | `@Claude` にメンションしてタスクを依頼 | チームのチャットからそのまま依頼したい |
| **GitHub Actions / GitLab CI** | CI パイプラインに組み込み | PR の自動レビュー、Issue のトリアージ |
| **Chrome 連携** | ブラウザ上の Web アプリをデバッグ | フロントエンドの実挙動を確認させたいとき |

### サーフェスをまたいで作業を移動できる

- `claude --cloud "..."` — ローカルからクラウドセッションを開始し、続きはスマホやブラウザで
- `claude --teleport` — Web で動かしていたセッションをターミナルに引き継ぐ
- `/desktop` — ターミナルのセッションをデスクトップアプリで継続
- `/remote-control` — ローカルのセッションをスマホやブラウザから操作

詳しくは [09 自動化とチーム利用](09-automation.md) を参照してください。

## 1-4. 必要なアカウントとプラン

Claude Code を使うにはアカウントが必要です。以下のいずれかで利用できます。

| 認証方法 | 説明 |
| --- | --- |
| **Claude サブスクリプション（推奨）** | Pro / Max / Team / Enterprise プラン。定額で使える |
| **Claude Console（API）** | 従量課金。プリペイドクレジットを使用。初回ログイン時に「Claude Code」ワークスペースが自動作成される |
| **クラウドプロバイダ経由** | Amazon Bedrock / Google Cloud の Agent Platform / Microsoft Foundry。企業向け |
| **自社ゲートウェイ経由** | 組織が Claude apps gateway を運用している場合、企業 SSO でログイン |

- 個人開発者なら **Pro または Max プランのサブスクリプション** が最も分かりやすい選択です。
- 料金の詳細は [claude.com/pricing](https://claude.com/pricing) を確認してください。
- コストの考え方・削減方法は [10 トラブルシューティング](10-troubleshooting.md#10-5-コストとトークンを節約する) にまとめています。

> **注意**
> Web 版（Claude Code on the web）は Pro / Max / Team、および premium seat などを持つ Enterprise ユーザー向けのリサーチプレビューとして提供されています。利用可否はプランによって変わります。

### 使えるモデル

`/model` で切り替えます。用途に応じて使い分けるとコストと精度のバランスが取れます。

| エイリアス | 用途 |
| --- | --- |
| `sonnet` | 最新の Sonnet。**日常のコーディングはこれで十分** |
| `opus` | 最新の Opus（現在は Opus 5）。複雑な推論・設計判断 |
| `haiku` | 高速・低コスト。単純な作業やサブエージェント向け |
| `fable` | 最も難しく長い作業向け。既定にはならない |
| `best` | Fable 5 が使えるならそれ、なければ最新の Opus |
| **`opusplan`** | **計画は Opus、実行は Sonnet** に自動で切り替える |
| `sonnet[1m]` / `opus[1m]` | 100万トークンのコンテキストウィンドウ |

Opus 5 と Sonnet 5 は**100万トークンのコンテキストウィンドウ**を持ちます（プロバイダによっては 1M 版の明示的な選択が必要）。
`opusplan` は「計画の質は担保しつつ実装コストは抑えたい」ときに便利です。

## 1-5. 使い始める前に知っておくとよいこと

**1. Claude Code は「見えている範囲」でしか判断できない**

起動したディレクトリ配下のファイルが作業対象です。プロジェクトのルートで起動するのが基本です。

**2. 変更は必ず確認できる**

デフォルトでは、ファイルを書き換える前・コマンドを実行する前に必ず許可を求めます。承認の頻度は設定で変えられます（[07 権限とセキュリティ](07-permissions-security.md)）。

**3. git は自分で管理しておくと安心**

Claude Code には変更を巻き戻す機能（チェックポイント）がありますが、これは Claude のファイル編集ツール経由の変更しか追跡しません。**git の代わりにはなりません。** 作業前にコミットしておく、ブランチを切っておく、といった普段の習慣はそのまま有効です。

**4. 万能ではない**

もっともらしいが微妙に間違っている実装を出すことがあります。だからこそ「Claude 自身が正しさを確認できる手段（テストなど）」を与えることが重要です。この考え方が [05 効果的な使い方](05-best-practices.md) の中心テーマです。
