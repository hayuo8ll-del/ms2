# 03. 基本操作

> **この章でわかること**
> - 起動・終了・再開のしかた
> - 情報の渡し方（`@` ファイル参照、画像、URL、パイプ）
> - スラッシュコマンドとキーボードショートカット
> - セッションとコンテキストの管理（`/clear`・`/compact`・`/rewind`）

---

## 3-1. 起動と終了

### 起動

```bash
cd /path/to/project
claude
```

最初のプロンプトを引数で渡すこともできます。

```bash
claude "ビルドエラーを直して"
```

### 終了

| 方法 | 説明 |
| --- | --- |
| `/exit` または `/quit` | セッションを終了 |
| `Ctrl+D` を2回 | 同上（1回目で確認、800ms 以内に2回目） |
| `Ctrl+C` | 実行中の処理を中断。何も動いていなければ入力をクリア、もう一度押すと終了 |

### 前回の続きから再開する

```bash
claude -c          # 直近の会話を再開（--continue）
claude -r          # 過去の会話を一覧から選んで再開（--resume）
claude -r "auth-refactor" "この PR を仕上げて"   # 名前を指定して再開
```

会話はローカルに保存されるので、ターミナルを閉じても、日をまたいでも続きから作業できます。

## 3-2. 対話の基本

普通の日本語で話しかけるだけです。同僚に頼むように書くのがコツです。

```text
このプロジェクトのテストはどうやって実行する？
```

```text
src/api/users.ts に入力バリデーションを追加して。
既存の src/api/posts.ts のバリデーションのやり方に合わせてね。
```

Claude Code はファイルを探し、読み、変更内容を提示し、（設定によっては）承認を求めてから編集します。

### 良い指示・惜しい指示

具体的であるほど、やり直しが減ります。

| 惜しい指示 | 良い指示 |
| --- | --- |
| `foo.py にテストを追加して` | `foo.py の「ユーザーがログアウトしている場合」のエッジケースのテストを書いて。モックは使わないで` |
| `ログインのバグを直して` | `セッションタイムアウト後にログインが失敗するという報告がある。src/auth/ の認証フロー、特にトークンのリフレッシュ処理を確認して。まず再現する失敗テストを書いてから直して` |
| `カレンダーウィジェットを追加して` | `ホーム画面の既存ウィジェットの実装（HotDogWidget.php が良い例）を見てパターンを把握して。同じパターンでカレンダーウィジェットを実装して。新しいライブラリは追加しないで` |

詳しくは [05 効果的な使い方](05-best-practices.md) を参照してください。

## 3-3. 情報の渡し方

### `@` でファイルを参照する

`@` を入力するとファイルパスの補完が出ます。指定したファイルは Claude が応答前に読み込みます。

```text
@src/auth/login.ts のエラーハンドリングを見直して
```

ファイルの場所を文章で説明するより速く、確実です。

### 画像を貼り付ける

スクリーンショットや UI のデザイン画像を、そのままプロンプトに貼り付け（またはドラッグ&ドロップ）できます。

| OS / 環境 | 貼り付け |
| --- | --- |
| macOS（iTerm2） | `Cmd+V` |
| 一般 | `Ctrl+V` |
| Windows / WSL | `Alt+V`（`Ctrl+V` が使えない場合） |

貼り付けると `[Image #1]` のようなチップが挿入され、プロンプト内で位置を指定して参照できます。

```text
[Image #1] このデザインの通りに実装して。実装後にスクリーンショットを撮って、
元の画像と比べて違いを列挙してから直して
```

### URL を渡す

ドキュメントや API リファレンスの URL をそのまま渡せます。よく使うドメインは `/permissions` で許可リストに入れておくと、毎回の確認が不要になります。

### パイプで流し込む

```bash
cat error.log | claude -p "このエラーの原因を教えて"
git diff main | claude -p "この差分をレビューして"
```

### `@` で他のセッションをメンションする

`@` に続けて名前を入力すると、ファイルだけでなく**あなたの他の Claude Code セッション**も候補に出ます。選ぶと、そのセッションにメッセージを送れます。

```text
@api-worker にスキーマ移行が終わったと伝えて
```

→ [09-3 セッション間でメッセージをやり取りする](09-automation.md#cross-session)

### シェルコマンドの結果を渡す（`!`）

プロンプトの先頭で `!` を入力すると **シェルモード** になります。コマンドを実行し、その出力をセッションに追加して、Claude に反応させられます。

```text
!npm test
```

## 3-4. スラッシュコマンド

`/` を入力するとコマンド一覧が表示されます。`/` に続けて文字を入力すると絞り込めます。
**コマンドはメッセージの先頭でのみ有効**です。

### まず覚える 10 個

| コマンド | 説明 |
| --- | --- |
| `/help` | 使えるコマンドの一覧を表示 |
| `/clear` | 会話をリセットして新しいコンテキストで始める |
| `/compact [指示]` | 会話を要約してコンテキストを節約する |
| `/context` | 今コンテキストに何が入っているかを可視化 |
| `/rewind` | コードと会話を過去のチェックポイントに巻き戻す |
| `/init` | プロジェクト用の `CLAUDE.md` を生成する |
| `/memory` | `CLAUDE.md` やオートメモリを編集する |
| `/permissions` | ファイル・コマンドの承認ルールを設定する |
| `/model` | 使用するモデルを切り替える |
| `/usage` | トークン使用量とコストを表示（`/cost` も同じ） |

### 覚えておくと便利なもの

| コマンド | 説明 |
| --- | --- |
| `/plan` | 次のプロンプトをプランモードで実行（変更せずに計画だけ立てる） |
| `/diff` | 未コミットの変更を差分ビューアで表示 |
| `/btw [質問]` | 会話履歴に残さずにちょっとした質問をする（コンテキストを汚さない） |
| `/rename` | セッションに名前を付ける（後で探しやすくなる） |
| `/resume` | 過去の会話に戻る |
| `/status` | 現在のセッションの状態を表示 |
| `/doctor` | 環境をチェックして問題と修正案を出す |
| `/code-review` | 現在の差分をバグ観点でレビューする（サブエージェントで実行） |
| `/security-review` | 差分をセキュリティ観点でチェックする |
| `/test [ファイル]` | テストを実行して失敗をデバッグする |
| `/agents` | サブエージェントの設定を管理 |
| `/hooks` | 設定されているフックを閲覧 |
| `/mcp` | MCP サーバーの接続状態を管理 |
| `/plugins` | プラグインを管理 |
| `/export` | 会話をテキストとして書き出す |
| `/copy` | 直前の応答をクリップボードにコピー |
| `/list-agents`（`/peers`） | メッセージを送れる他のセッションを一覧表示 |
| `/subtask [指示]` | 会話を引き継いだサブエージェント（fork）に脇道作業を渡す |
| `/design [指示]` | UI の設計案をアートボードとして描かせる |

全コマンドは [11 コマンド早見表](11-cheatsheet.md) にまとめています。

> **補足**
> コマンドには「CLI に処理が組み込まれた組み込みコマンド」と「Claude に渡されるプロンプトであるスキル」の 2 種類があります（`/code-review` や `/doctor` はスキル）。使う側から見た違いはほとんどありません。自分で作ることもできます → [08 拡張機能](08-extensions.md)

## 3-5. キーボードショートカット

### 最重要の 4 つ

| ショートカット | 動作 |
| --- | --- |
| **`Esc`** | Claude を中断する。途中までの作業は保持されるので、方向修正して続けられる |
| **`Esc` `Esc`**（2回） | 入力欄が空なら**巻き戻しメニュー**を開く。入力があれば入力をクリア |
| **`Shift+Tab`** | 権限モードを切り替える（Manual → 編集自動承認 → プランモード → …） |
| **`Ctrl+G`** | 入力中のプロンプト（やプラン）を外部エディタで開いて編集する |

### 全般

| ショートカット | 動作 |
| --- | --- |
| `Ctrl+C` | 実行中の処理を中断／入力をクリア（何も動いていなければ2回で終了） |
| `Ctrl+D` | セッションを終了（2回押し） |
| `Ctrl+L` | 画面を再描画（表示が崩れたとき） |
| `Ctrl+O` | トランスクリプトビューアの表示切替（ツールの実行内容を詳細表示） |
| `Ctrl+R` | コマンド履歴を逆順検索 |
| `Ctrl+B` | 実行中のタスクをバックグラウンドに送る |
| `Ctrl+T` | Claude の TODO チェックリストの表示切替 |
| `Ctrl+S` | 入力中のテキストを一時退避／復元 |
| `↑` / `↓` | カーソル移動、または（先頭・末尾行で）コマンド履歴の移動 |
| `Alt+P`（macOS は `Option+P`） | モデルを切り替える |
| `Alt+T`（macOS は `Option+T`） | 拡張思考（extended thinking）のオン/オフ |
| `Alt+O`（macOS は `Option+O`） | 高速モード（fast mode）のオン/オフ |
| `?`（入力が空のとき） | ショートカットのヘルプパネル |

### 複数行を入力する

| 方法 | キー | 備考 |
| --- | --- | --- |
| バックスラッシュ | `\` → `Enter` | どのターミナルでも動く |
| Shift+Enter | `Shift+Enter` | iTerm2、WezTerm、Ghostty、Kitty、Warp、Apple Terminal、Windows Terminal では設定不要 |
| コントロールシーケンス | `Ctrl+J` | 設定不要でどこでも動く |
| Option+Enter | `Option+Enter` | macOS で Option を Meta として設定した場合 |

VS Code、Cursor、Alacritty、Zed で `Shift+Enter` を使いたい場合は `/terminal-setup` を実行してください。

### テキスト編集（readline 互換）

| ショートカット | 動作 |
| --- | --- |
| `Ctrl+A` / `Ctrl+E` | 行頭 / 行末へ移動 |
| `Ctrl+K` / `Ctrl+U` | カーソル以降 / 以前を削除 |
| `Ctrl+W` | 直前の単語を削除 |
| `Ctrl+Y` | 削除したテキストを貼り付け |
| `Alt+B` / `Alt+F` | 単語単位で前後に移動 |

> **macOS で `Alt`（`Option`）系が効かない場合**
> ターミナル側で Option を Meta キーとして扱う設定が必要です。
> - iTerm2: Settings → Profiles → Keys → General → Left/Right Option key を "Esc+" に
> - Apple Terminal: Settings → Profiles → Keyboard → "Use Option as Meta Key" にチェック
> - VS Code: 設定に `"terminal.integrated.macOptionIsMeta": true` を追加

### Vim キーバインドを使いたい場合

`/config` → Editor mode から vim モードを有効にできます。`Esc` で NORMAL モード、`i` / `a` / `o` などの基本操作が使えます。

## 3-6. 応答のスタイルを変える

Claude の返答の書き方は、**出力スタイル**で変えられます。`/config` の **Output style** から選ぶか、設定ファイルに書きます。

```json
{ "outputStyle": "Concise" }
```

| スタイル | 内容 |
| --- | --- |
| **Default** | 標準 |
| **Concise** | **結果から書き始め、前置きと実況を省く。** 作業の丁寧さは Default と同じ |
| **Proactive** | 確認を挟まず即実行する。auto モードより強い自律実行の指示 |
| **Explanatory** | 作業しながら解説を挟む |
| **Learning** | `TODO(human)` を置いて、一部をあなたに実装させる |

反映には `/clear` か新しいセッションが必要です（システムプロンプトの一部のため）。

> **Concise でも情報は削られません。** 説明を求めれば詳しく答えますし、エラー報告・セキュリティ警告・破壊的操作の確認は常に完全な内容が表示されます。

## 3-7. セッションとコンテキストの管理

ここは **Claude Code を使いこなす上で最も効く知識** です。

### コンテキストウィンドウとは

Claude が一度に「覚えていられる」情報の量です。会話のすべて、読んだファイルの中身、実行したコマンドの出力が、すべてここに積み上がっていきます。

**そして、いっぱいに近づくほど性能は落ちます。** 前の指示を忘れたり、ミスが増えたりします。
だからコンテキストは意識的に管理する必要があります。

### `/context` で今の状態を見る

```text
/context
```

何がどれだけコンテキストを占めているかが色分けされたグリッドで表示されます。`CLAUDE.md` が読み込まれているかの確認にも使えます。

### `/clear` — 別の作業に移るときは必ず

```text
/clear
```

会話履歴を完全にリセットします。**関連のないタスクに移るときは毎回実行する**くらいの気持ちで構いません。前のタスクの情報が残っていると、判断を鈍らせます。

### `/compact` — 文脈は保ちつつ圧縮する

```text
/compact
/compact API の変更点を中心に残して
```

会話を要約してコンテキストを空けます。今の作業の続きをやりたいが容量が苦しい、というときに使います。
コンテキストが限界に近づくと**自動で圧縮（オートコンパクション）が走ります**。

### `/rewind` — 巻き戻す

`Esc` を2回押すか `/rewind` で巻き戻しメニューが開きます。

**送信したプロンプトごとにチェックポイントが自動保存されている**ので、以下を選べます。

- 会話だけ巻き戻す
- コードだけ巻き戻す
- 両方巻き戻す
- 選んだ地点から先を要約する / 手前までを要約する

「ちょっとリスクのある方法を試してみて、ダメなら巻き戻す」という使い方ができます。

> **重要な注意**
> チェックポイントが追跡するのは **Claude のファイル編集ツールを通した変更だけ** です。
> Bash コマンドや外部プロセスによる変更は含まれません。**git の代替にはなりません。**

### `/rename` でセッションに名前を付ける

```text
/rename oauth-migration
```

セッションを git のブランチのように扱えます。作業ごとに名前を付けておくと `claude -r` で探しやすくなります。

### `/btw` — コンテキストを汚さずに質問する

```text
/btw git の rebase と merge の違いって何だっけ？
```

答えは消せるオーバーレイに表示され、**会話履歴には残りません**。作業の流れを止めずにちょっと確認したいときに便利です。

## 3-8. 権限モードの切り替え（さわりだけ）

`Shift+Tab` を押すと権限モードが切り替わります。ステータスバーに現在のモードが表示されます。

> **2026年8月14日以降、Pro / Max / Team プランの既定は `auto` モードです。** 慎重に進めたいときは `Shift+Tab` で Manual に切り替えてください。

| モード | 確認なしで実行されること | 使いどころ |
| --- | --- | --- |
| **Manual**（`default`） | 読み取りのみ | 最初のうち、慎重に進めたいとき |
| **acceptEdits** | 読み取り＋ファイル編集＋基本的なファイル操作コマンド | 差分を後でまとめて確認するとき |
| **plan** | 読み取りのみ（編集はブロック） | 変更前に調査・計画したいとき |
| **auto** | ほぼすべて（別モデルが危険な操作をブロック） | 長めの作業を任せたいとき |

詳しくは [07 権限とセキュリティ](07-permissions-security.md) を参照してください。
