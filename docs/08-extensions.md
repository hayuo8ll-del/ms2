# 08. 拡張機能（スキル・フック・MCP・サブエージェント・プラグイン）

> **この章でわかること**
> - どの拡張機能を、どういうときに使うのか（判断基準）
> - スキル・フック・MCP・サブエージェント・プラグインそれぞれの作り方
> - 拡張機能ごとのコンテキストコスト

---

## 8-1. まず「どれを使うか」を決める

拡張機能は 5 種類ありますが、**解決する問題がそれぞれ違います。**

| 機能 | 何をするもの | 使いどころ | 例 |
| --- | --- | --- | --- |
| **CLAUDE.md** | 毎回のセッションで読み込まれる常時コンテキスト | プロジェクトの規約、「常に X する」ルール | 「npm ではなく pnpm を使う。コミット前にテストを実行する」 |
| **スキル** | Claude が使える知識・手順・ワークフロー | 再利用する内容、参照資料、繰り返す作業 | `/deploy` でデプロイ手順を実行。API スタイルガイド |
| **サブエージェント** | 隔離されたコンテキストで動き、要約だけ返す実行単位 | コンテキストの隔離、並列作業、専門特化 | 大量のファイルを読む調査タスク |
| **MCP** | 外部サービスへの接続 | 外部のデータや操作が必要なとき | DB への問い合わせ、Slack への投稿、ブラウザ操作 |
| **フック** | ライフサイクルイベントで起動するスクリプト等 | 毎回必ず起きてほしい自動処理 | ファイル編集のたびに ESLint を実行 |
| **プラグイン** | 上記をまとめて配布する packaging | 複数リポジトリで同じ構成を使い回す | 社内共通のレビュー設定一式 |

### 段階的に増やしていく

最初から全部そろえる必要はありません。**「こういう困りごとが出たら、これを足す」** という順番で育てるのが実践的です。

| 困りごと | 追加するもの |
| --- | --- |
| 同じ規約やコマンドを 2 回間違えられた | [CLAUDE.md](06-claude-md.md) に書く |
| 同じプロンプトを毎回打っている | 自分で呼び出す**スキル**にする |
| 同じ手順書を 3 回目のチャットに貼り付けた | **スキル**にする |
| Claude が見られないブラウザタブからデータをコピーしている | その仕組みを **MCP サーバー**として接続する |
| 後で見返さない大量の出力で会話が埋まる | **サブエージェント**に回す |
| 聞かなくても毎回やってほしいことがある | **フック**を書く |
| 2 つ目のリポジトリでも同じ構成が必要になった | **プラグイン**にまとめる |

### 似ている機能の使い分け

**スキル vs サブエージェント**

| | スキル | サブエージェント |
| --- | --- | --- |
| 正体 | 再利用可能な指示・知識・手順 | 独自のコンテキストを持つ隔離ワーカー |
| 主な利点 | 内容をどのコンテキストにも読み込める | コンテキストの隔離。要約だけが返る |
| コンテキストへの影響 | メインのウィンドウに加算される | 別ウィンドウを使う |
| 向いているもの | 参照資料、呼び出せるワークフロー | 大量のファイルを読む作業、並列作業 |

**CLAUDE.md vs スキル**

- **常に知っておいてほしいこと** → CLAUDE.md（コーディング規約、ビルドコマンド、「絶対に X しない」）
- **時々必要な参照資料や、`/名前` で呼び出す手順** → スキル（API ドキュメント、デプロイ手順、リリース手順）
- 目安: **CLAUDE.md は 200 行以内**。増えてきたらスキルか `.claude/rules/` に移す

**フック vs スキル**

| | フック | スキル |
| --- | --- | --- |
| 実行されるもの | シェルコマンド、HTTP リクエスト、プロンプト、サブエージェント | Claude が読んで従う指示 |
| きっかけ | ライフサイクルイベント（`PostToolUse` など） | `/名前` の入力、または Claude の判断 |
| 確実性 | **必ず発火する（保証される）** | Claude が解釈するので結果は揺れる |
| コンテキストコスト | ゼロ（出力を返さない限り） | 説明文が毎セッション、本文は使用時 |

> **ガードレールはフックに置く。**
> 「`.env` は絶対に編集しない」を CLAUDE.md やスキルに書くのは**お願い**であって保証ではありません。
> `PreToolUse` フックで編集をブロックすれば、それは**強制**になります。

**MCP vs スキル**

MCP は外部システムへの「接続」、スキルはそれを「うまく使う知識」です。組み合わせると強力です。
例: MCP がデータベースに接続し、スキルがデータモデル・よく使うクエリ・どのテーブルを使うべきかを教える。

## 8-2. スキル（Skills）

### スキルとは

`SKILL.md` という Markdown ファイルに指示を書くと、Claude の道具箱に追加されます。
**Claude が関連すると判断したときに自動で読み込まれる**か、**`/スキル名` で自分で呼び出す**ことができます。

CLAUDE.md と違い、**本文は使うときにだけ読み込まれる**ので、長い参照資料を置いてもコンテキストをほとんど消費しません。

> カスタムコマンドはスキルに統合されました。`.claude/commands/deploy.md` と `.claude/skills/deploy/SKILL.md` はどちらも `/deploy` を作り、同じように動きます。既存の `.claude/commands/` はそのまま使えます。

### 置き場所

| スコープ | パス | 適用範囲 |
| --- | --- | --- |
| 個人 | `~/.claude/skills/<スキル名>/SKILL.md` | 自分の全プロジェクト |
| プロジェクト | `.claude/skills/<スキル名>/SKILL.md` | そのプロジェクトのみ（git 共有可） |

ディレクトリ名がそのままコマンド名になります（`.claude/skills/deploy-staging/SKILL.md` → `/deploy-staging`）。

### 例 1: 知識を持たせるスキル

```markdown
---
name: api-conventions
description: このコードベースの API 設計規約
---

# API 規約

- URL パスは kebab-case
- JSON のプロパティは camelCase
- 一覧系のエンドポイントには必ずページネーションを付ける
- API はパスでバージョニングする（/v1/, /v2/）
```

`description` は **Claude がこのスキルを使うべきか判断するための情報**です。曖昧だと呼ばれません。具体的に書いてください。

### 例 2: 手順を実行するスキル

```markdown
---
name: fix-issue
description: GitHub の Issue を修正する
disable-model-invocation: true
---

GitHub Issue を分析して修正する: $ARGUMENTS

1. `gh issue view` で Issue の詳細を取得する
2. 記述されている問題を理解する
3. 関連するファイルをコードベースから探す
4. 修正を実装する
5. テストを書いて実行し、修正を検証する
6. Lint と型チェックが通ることを確認する
7. 分かりやすいコミットメッセージを作る
8. プッシュして PR を作る
```

`/fix-issue 1234` のように呼び出します。`$ARGUMENTS` に引数が入ります。

### 主なフロントマター

| フィールド | 説明 |
| --- | --- |
| `name` | スキル名（必須） |
| `description` | 何をするスキルか。Claude の判断材料になる（必須） |
| `disable-model-invocation` | `true` にすると Claude は自動で呼ばず、あなたが `/名前` で呼んだときだけ動く |
| `allowed-tools` | このスキル実行中、確認なしで使えるツール |
| `disallowed-tools` | このスキル実行中に使わせないツール |
| `context: fork` | スキルを独自のサブエージェントコンテキストで実行する（既定でバックグラウンド。`background: false` で同じターンで待つ） |

> **副作用のあるワークフローには `disable-model-invocation: true` を。**
> デプロイやコミットのように「勝手に実行されたら困る」ものは、必ず手動起動にしてください。コンテキストコストもゼロになります。

### 最初から入っているスキル

自分で作らなくても、すぐ使えるスキルがあります。

| スキル | 説明 |
| --- | --- |
| `/code-review` | 差分をバグ・改善観点でレビュー |
| `/security-review` | 差分をセキュリティ観点でチェック |
| `/test` | テストを実行して失敗をデバッグ |
| `/simplify` | コードの簡素化・整理を提案して適用 |
| `/doctor` | 環境をチェックして問題を修正 |
| `/debug` | デバッグログを有効化して問題を切り分け |
| `/batch` | 大規模な変更をコードベース全体に並列適用 |
| `/pr-feedback` / `/pr-summary` | GitHub PR のフィードバック取得・要約 |
| `/loop` | プロンプトを一定間隔で繰り返し実行 |
| `/design` | UI の設計案を編集可能なアートボードとして複数枚描く（リサーチプレビュー） |

> `/verify`、`/code-review`、`/deep-research` は**あなたが呼び出したときだけ動きます。** Claude が自分の判断で起動することはありません。
> `/code-review` はすべての効果レベルでバックグラウンドのサブエージェントとして動くので、レビューの過程がメインの会話を埋めません。

### スキルを作らせる

自分で書かなくても、Claude に作らせられます。

```text
デプロイ手順のスキルを作って。手順は以下の通り: ...
```

---

### 使われていないスキルを見つける（`/skill-doctor`）

**スキルは、使われなくても説明文が毎ターンのコンテキストに載ります。** `/skill-doctor` は、各スキルが**コンテキストをどれだけ消費しているか**と**どれだけ使われているか**を一覧にして、外してよいものの判断材料を出します（v2.1.252 以降）。

```text
/skill-doctor
```

対話セッションでは `/plugin` の **Stats** タブに表示され、`-p`（非対話）ではテキストで出力されます。`/skills` の一覧では `t` キーでトークン数順に並べ替えられます。

- 手動でしか使わないスキルは `disable-model-invocation: true` にすると、コンテキスト消費がゼロになります
- スキルや指示ファイルを**古いモデル向けの書き方のまま**放置していないか調べるには、`/doctor prompt-audit`（`CLAUDE.md`・スキル・エージェント・コマンドを診断）が使えます
- `verify` という名前のスキルがあると、Claude はコミット前にそれを実行します（ドキュメントのみ・テストのみのコミットを除く）

## 8-3. フック（Hooks）

### フックとは

Claude Code のライフサイクルの特定のタイミングで、**あなたが指定したコマンドを必ず実行する**仕組みです。
CLAUDE.md の指示が「お願い」なのに対し、フックは**決定論的**です。

### 主なイベント

| イベント | タイミング |
| --- | --- |
| `SessionStart` | セッション開始・再開時 |
| `UserPromptSubmit` | プロンプト送信時（Claude が処理する前） |
| `PreToolUse` | ツール実行の直前（**ブロックできる**） |
| `PermissionRequest` | 権限の判断が必要になったとき（**`agent` 型のフックは動かなくなりました。** `command` か `http` 型を使います） |
| `PostToolUse` | ツール実行の成功後 |
| `Notification` | 通知が送られるとき（入力待ちなど） |
| `Stop` | Claude が応答を終えたとき（**ターン終了をブロックできる**） |
| `SubagentStop` | サブエージェントが終了したとき |
| `PreCompact` | コンテキスト圧縮の前 |
| `SessionEnd` | セッション終了時 |
| `InstructionsLoaded` | `CLAUDE.md` や `.claude/rules/*.md` が読み込まれたとき |
| `Setup` | `--init-only` などでの一度きりの準備処理 |
| `PreModelSwitch` / `PostModelSwitch` | モデルの切り替え前（**ブロックできる**）／切り替え後（Claude に文脈を足せる） |

### 設定の書き方

設定ファイル（`~/.claude/settings.json` や `.claude/settings.json`）に `hooks` ブロックを追加します。

**例: ファイル編集後に Prettier をかける**

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"
          }
        ]
      }
    ]
  }
}
```

**例: Claude が入力待ちになったら macOS で通知する**

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code needs your attention\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}
```

すでに `hooks` キーがある場合は、**イベント名を兄弟キーとして追加**してください（オブジェクトごと置き換えないこと）。

`matcher` にはツール名を指定します（`Bash`、`Edit|Write`、`mcp__.*` など）。空文字はすべてにマッチします。

### フックが失敗したときの扱い

コマンド型・HTTP 型のフックには `onFailure: "block"` を指定できます。**フックが失敗またはタイムアウトしたとき、そのアクションをブロック**します（既定では通ってしまいます）。「必ず通らないと進ませたくない」ガードレールに使ってください。

```json
{ "type": "command", "command": "~/.claude/hooks/check.sh", "onFailure": "block" }
```

> `UserPromptSubmit` フックは、**スキルやコマンドの展開より前**に実行されます（v2.1.299〜）。

### 確認する

```text
/hooks
```

`/hooks` は、イベントごとにまとまった 1 つの一覧で開きます。

設定されているフックの一覧が見られます。**このメニューは閲覧専用**です。追加・変更は設定ファイルを直接編集するか、Claude に頼んでください。

### 作らせる

```text
ファイル編集のたびに eslint を実行するフックを書いて
```

```text
migrations フォルダへの書き込みをブロックするフックを書いて
```

### 応用: トークン節約に使う

10,000 行のログを Claude に読ませる代わりに、フックで `ERROR` を含む行だけ抽出して返せば、コンテキストは数万トークンから数百トークンに減ります。

## 8-4. MCP（外部ツールとの連携）

### MCP とは

**Model Context Protocol** は、AI ツールを外部データソースに接続するためのオープン標準です。
MCP サーバーを接続すると、Claude Code がそのツール・データベース・API を直接扱えるようになります。

**「別のツールからチャットにデータをコピーしている」と気づいたら、それは MCP を接続するサインです。**

### できることの例

```text
JIRA の ENG-4521 に書かれている機能を実装して、GitHub に PR を作って
```

```text
PostgreSQL のデータベースから、ENG-4521 の機能を使ったユーザーを 10 人ランダムに抽出して
```

```text
Slack に投稿された新しい Figma デザインを元に、メールテンプレートを更新して
```

### サーバーを追加する

**HTTP（リモートサーバー、最も一般的）**

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
```

**SSE**

```bash
claude mcp add --transport sse asana https://mcp.asana.com/sse
```

**stdio（ローカルプロセス）**

```bash
claude mcp add --transport stdio airtable --env AIRTABLE_API_KEY=YOUR_KEY \
  -- npx -y airtable-mcp-server
```

`--` の後ろが実際に実行されるコマンドです。

追加できると `Added ...` と表示されます。接続状態は `claude mcp list` で確認できます（`✔ Connected` / `! Needs authentication` / `✘ Failed to connect`）。

### スコープ（どこに保存されるか）

| スコープ | 保存先 | 共有範囲 |
| --- | --- | --- |
| **local**（デフォルト） | `~/.claude.json` のプロジェクト別セクション | 自分だけ、そのプロジェクトのみ |
| **project** | プロジェクトルートの `.mcp.json` | **git にコミットしてチーム共有** |
| **user** | `~/.claude.json` | 自分だけ、全プロジェクト |

```bash
claude mcp add --transport http shared-server --scope project https://example.com/mcp
claude mcp add --transport http hubspot --scope user https://mcp.hubspot.com/anthropic
```

優先順位は **local > project > user** です。同じ名前があれば優先度の高いものが使われます（フィールドのマージはされません）。

> **セキュリティ**
> `.mcp.json` で定義されたプロジェクトスコープのサーバーは、使用前に承認を求められます。承認をやり直したい場合は `claude mcp reset-project-choices` を実行してください。

### 管理する

```text
/mcp
```

接続状態の確認、再接続、有効化・無効化、OAuth 認証ができます。接続に失敗したサーバーをまとめて再試行するなら `/mcp reconnect all` です。シェルから OAuth を済ませるなら `claude mcp login <名前>` が使えます。**使っていないサーバーは無効化しておくとコンテキストの節約になります。**

### コンテキストコストについて

MCP サーバーのツール定義は**デフォルトで遅延読み込み**されます。ツール名だけがコンテキストに入り、実際に使うときにスキーマが読み込まれます。そのため、繋いでいるだけならコストはわずかです。

ただし、**`gh`・`aws`・`gcloud` のような CLI ツールが使えるならそちらのほうが効率的です。** ツール一覧の分すら消費しないためです。

## 8-5. サブエージェント（Subagents）

### サブエージェントとは

**独自のコンテキストウィンドウ・システムプロンプト・ツール権限を持つ、専門特化した実行単位**です。
大量のファイルを読む調査などを任せると、**その作業はサブエージェント側のコンテキストで行われ、メインの会話には要約だけが返ります。**

これは [05 効果的な使い方](05-best-practices.md) で述べた「コンテキストが最大の制約」への直接的な対策になります。

### 使い方（一番簡単な方法）

頼むだけです。

```text
サブエージェントを使って、認証まわりでトークンリフレッシュがどう実装されているか調べて
```

```text
サブエージェントを使って、この差分のエッジケースをレビューして
```

> **対話セッションでは既定でバックグラウンド実行されます。** 待たされずに作業を続けられ、結果は完了時に会話へ返ります。

### fork — 会話を引き継ぐサブエージェント

通常のサブエージェントは白紙から始まるため、背景を説明し直す必要がありました。**fork 型は、それまでの会話全体とプロンプトキャッシュを引き継ぎます。**

```text
/subtask ここまでのパーサー変更に対するユニットテストを書いて
```

「ここまでの」と書くだけで通じるのが fork の利点です。**既定で有効**で、無効にするには `CLAUDE_CODE_FORK_SUBAGENT=0` を設定します。

| | 通常のサブエージェント | fork |
| --- | --- | --- |
| 開始時のコンテキスト | 白紙（渡した指示のみ） | **会話全体を引き継ぐ** |
| 向いている用途 | 独立した調査、大量のファイル読み | これまでの議論を踏まえた脇道作業 |
| コンテキスト効率 | 高い | キャッシュを共有するので追加コストは小さい |

### 同時実行と上限

- 1 セッションあたりのサブエージェント総数の上限（200）は**撤廃されました**
- 同時実行は既定で 20。`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` で変更できます
- `--max-budget-usd` の上限はサブエージェントにも効きます。到達すると新規起動が止まり、実行中のものも停止します

### カスタムサブエージェントを定義する

`.claude/agents/`（プロジェクト）または `~/.claude/agents/`（個人）に Markdown ファイルを置きます。

```markdown
---
name: security-reviewer
description: セキュリティ脆弱性の観点でコードをレビューする
tools: Read, Grep, Glob, Bash
model: opus
---
```

## 8-6. プラグイン（Plugins）

スキル・フック・サブエージェント・MCP サーバーを**1 つのインストール可能な単位にまとめたもの**です。
コミュニティや Anthropic が公開しているものを使えます。

```text
/plugins
```

マーケットプレイスを閲覧してインストールできます。CLI からも操作できます。

```bash
claude plugin install code-review@claude-plugins-official
```

プラグインのスキルは名前空間が付くので（`/my-plugin:review`）、複数のプラグインが共存できます。

### 知っておくと良いプラグイン

**Claude Security** は、複数のエージェントによる脆弱性スキャンをセッション内で実行します。アーキテクチャの把握 → 脅威モデル作成 → 脆弱性探索 → 各指摘の独立レビュー、という流れで結果を書き出し、選んだ指摘をパッチに変換できます（適用は自分で行います）。

```text
/plugin install claude-security@claude-plugins-official
/reload-plugins
/claude-security
```

リポジトリ全体でも、ブランチの差分・PR・単一コミットだけでもスキャンできます。

### プラグインを作る・検証する人向け

**`claude plugin eval` — プラグインをテストする**（v2.1.269〜）

プラグインを**テストケースの集合で採点**します。既定では、同じケースを**プラグインなしでも実行して比較**するので、そのプラグインが何を足しているかが数字で分かります。

```bash
claude plugin eval init     # 何を良しとするかを聞かれ、ケースと採点基準を提案・生成する
claude plugin eval .        # 全ケースを採点（結果は evals/results/report.html にも出る）
```

> 各実行と、別のモデルが採点する検査は、**実際のモデル呼び出しとしてあなたのアカウントに課金**されます。git 2.31 以降が必要です。

**Mods（モッド）**（v2.1.287〜）

プラグインが、**Claude Code の挙動をより深く変える**仕組みです。ペインやステータス行、スラッシュコマンド、ツール呼び出しへのフックなどを足せます。作るときは `/plugin-authoring` で参考資料を読み込ませます。組み込みの例として、見落としを指摘する副エージェント **「You should know」** があります（`/plugin enable cc-plugin-you-should-know@builtin`。テレメトリが有効な一部のセッションのみ）。

**インストールの安全性**

- npm ソースのプラグインは `npm pack --ignore-scripts` で取得され、**整合性が検証されます**（インストールスクリプトは実行されません）
- `claude plugin install` / `update` に `--accept-command <sha256>` を渡すと、**確認したコマンドのハッシュを明示して**承認できます
- `claude plugin install <名前> --marketplace <ソース>` は、必要ならマーケットプレイスを追加してからインストールします
- 先頭に `--json` を付けると、結果を 1 つの JSON として出力できます（`install` / `uninstall` / `update` / `enable` / `disable`）

### 配布形式

マーケットプレイスは git だけでなく、**zip アーカイブ**（`archive` ソース、SHA-256 のピン留め可）や、プラグインの場所を出力する**ローカルコマンド**（`command` ソース）からも配布できます。`gitlab.com` の URL もそのまま使えます。

> **型付き言語を使っているなら**
> **コードインテリジェンスプラグイン**の導入を強く推奨します。言語サーバーと接続され、シンボル単位の正確な定義ジャンプと、編集後の型エラー自動検出ができるようになります。grep で候補ファイルを何個も読む代わりに 1 回の定義ジャンプで済むので、**コンテキストの節約にもなります。**

複数リポジトリで同じ構成を使い回したい、チームに配布したい場合は、自分でプラグインを作ってマーケットプレイスで配布することもできます。

## 8-7. コンテキストコストの比較

| 機能 | 読み込まれるタイミング | 読み込まれるもの | コスト |
| --- | --- | --- | --- |
| **CLAUDE.md** | セッション開始 | 全文 | 毎リクエスト |
| **スキル** | 開始時＋使用時 | 開始時は説明文のみ、本文は使用時 | 低（`disable-model-invocation: true` ならゼロ） |
| **MCP サーバー** | セッション開始 | ツール名のみ（スキーマは遅延） | 使うまでは低い |
| **コードインテリジェンス** | 編集後・必要時 | 型エラー、シンボル情報 | 低（むしろファイル読み込みが減る） |
| **サブエージェント** | 起動時 | 別コンテキスト | メインからは隔離 |
| **フック** | イベント発火時 | なし（外部で実行） | ゼロ（出力を返さない限り） |
