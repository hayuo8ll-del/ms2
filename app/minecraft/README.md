# マイクラ建築図面ジェネレータ

**レイヤー（Y 座標）ごとの平面図**と**材料表**が出る Web アプリです。

**公開 URL**: https://hayuo8ll-del.github.io/ms2/minecraft/

入力は 3 通りあり、出力（平面図・立面図・全レイヤー・材料表・テキスト・コマンド）は共通です。

| 入力 | 中身 |
| --- | --- |
| **形から作る** | 円 / 楕円 / 円柱、球 / 楕円体、ドーム、円錐 / 尖塔、切妻・寄棟・片流れ屋根、螺旋階段、アーチ |
| **ファイルを読む** | 公開されている建築やトラップの `.litematic` / `.schem` / `.nbt` |
| **実際の建物** | 有名建築のプリセット、または現実の寸法（メートル）とスケールから |

---

## なぜ作ったか

マイクラで詰まるのは、たいてい**計算しないとブロックの位置が決まらない形**です。
半径 9 の球の 4 段目がどんな円になるか、幅 13 の寄棟屋根の 3 段目で階段をどっち向きに置くかは、
手で割り出すと時間がかかるうえ、途中で 1 マスずれると最後まで気づけません。

配布されている建築やトラップも同じで、ファイルを開ける環境がないと中身が見えず、
何がいくつ要るのかも分かりません。

このアプリは、**立体 → 各段の平面図と材料表**の変換をやります。
図面を見ながら下から積めば形が出ます。

---

## 使い方

1. ページを開く（またはこのディレクトリの `index.html` を直接開く）
2. 左上で入力を選ぶ（**形から作る** / **ファイルを読む** / **実際の建物**）
3. 右の平面図をスライダーか `←` `→` キーで送りながら、下の段から積む
4. 「材料」タブで、用意するブロックと個数を確かめる

| タブ | 中身 |
| --- | --- |
| 平面図 | 現在の段の平面図と、中心を通る立面図。一つ下の段が薄く重なる |
| 完成イメージ | 積み上がった姿を等角投影で見る。回転・積み上げ途中の表示・PNG 保存 |
| 全レイヤー | 全段を並べたコンタクトシート。印刷向き |
| 材料 | ブロックごとの個数とスタック換算。段ごとの内訳も出せる |
| テキスト | 記号グリッドの図面。チャットやメモに貼れる |
| コマンド | `setblock` の列（`.mcfunction`） |

### 公開されている建築・トラップを読む

読み込む方法は 2 つあります。**ファイルはブラウザの中だけで読み、どこにも送信しません。**

1. **配布元から選ぶ** — GitHub の公開リポジトリを `owner/repo` で指定すると、中の
   `.litematic` / `.schem` / `.nbt` を一覧し、クリックでそのまま図面になります。
   `owner/repo@branch` でブランチも指定できます。開いた直後は**同梱サンプル**が並んでいるので、
   すぐ試せます
2. **ドロップする** — 手元のファイルをページのどこにでも落とす

#### 配布元について

ブラウザから取りに行けるのは、CORS を許している相手だけです。GitHub は API も
`raw.githubusercontent.com` も許しているので直接読めます。一方、
**minecraft-schematics.com や PlanetMinecraft は CORS ヘッダを返さず公開 API も無いため、
静的ページからは取得できません**（ブラウザの仕様上の制限です）。
それらのサイトのものは、ダウンロードしてからドロップしてください。

GitHub API は**ログインなしだと 1 時間に 60 回まで**です。上限に達したときは、
復帰時刻を添えてその旨を出します。一覧を開くのに 1〜2 回使うので、通常の使い方で困ることはありません。

置き場を探すときは、アプリ内のリンクから GitHub のリポジトリ検索に飛べます。
特定のリポジトリを初期値として同梱してはいません（消えたり中身が変わったりして、
空の一覧を出すことになるため）。一度開いたリポジトリは履歴に残り、次から 1 クリックで開けます。

| 形式 | 出どころ |
| --- | --- |
| `.litematic` | Litematica（建築配布でいちばん多い） |
| `.schem` | Sponge v2 / v3（WorldEdit、配布サイト） |
| `.nbt` | ストラクチャーブロック |

同梱サンプル（`samples/`）は `tools/make_samples.py` が生成した自前のデータで、
第三者の作品ではありません。3 形式とも中身は同じです。

トラップのように向きが動作に効くものは、`facing` を矢印で図面に出します。
上下向き（ホッパーやオブザーバー）は矢印にできないので、**● が下向き、○ が上向き**です。

読める大きさは一辺 512 ブロック・のべ 800 万マスまでです。超えるものは理由を出して止めます。

### 有名建築から起こす

建物の名前を入れて選ぶと、実寸に合わせた図面と材料表が出ます。収録しているのは 11 件です。

| 収録 | 建物 |
| --- | --- |
| 日本 | 姫路城、五重塔（法隆寺）、厳島神社 大鳥居、東大寺 大仏殿 |
| 世界 | タージ・マハル、ギザの大ピラミッド、コロッセオ、ピサの斜塔 |
| 近代 | エッフェル塔、東京タワー、凱旋門 |

**実測の再現ではありません。** 既存の部品（箱・台形・四角錐・円柱・ドーム・屋根・アーチ）を
組み合わせて、ブロックで積める形に単純化した外形です。ドームや屋根の曲面、装飾、内部の間取りは
入っていません。そのぶん、**外形の寸法は実寸に合わせてあり**（実寸÷スケールと ±20% 以内。
セルフテストで担保）、材料表はそのまま使えます。

- **1 ブロック = 何 m** を変えると、大きく精密にも、小さく手軽にもできます。
  建物ごとに、マイクラで積める大きさに収まる既定値を入れてあります
- **外面だけにする** で中身をくり抜けます。ギザの大ピラミッドは詰めると 31 万ブロックですが、
  外面だけなら実際に建てられる量になります

### 寸法から起こす

現実の寸法をメートルで入れ、**1 ブロックを何メートルとして建てるか**を決めると、
換算結果（`9.1m ÷ 1 = 9 ブロック`）を見ながら図面を作れます。
壁・床・窓・屋根はそれぞれ別のブロックを指定できます。
階高に収まらない窓や玄関は切り詰めたうえで警告が出ます。

**図面 URL をコピー**を押すと、いまの寸法が入った URL が取れます。入力内容はブラウザの
localStorage にだけ保存され、外部には送信されません。

### URL パラメータ

| パラメータ | 動作 |
| --- | --- |
| `?shape=dome&rx=12&ry=8&rz=12` | 形状と寸法を指定して開く（パラメータ名は `index.html` の `FIELDS` のキー） |
| `?tab=sheet` | 全レイヤー一覧を開いた状態にする（印刷したいとき） |
| `?selftest=1` | 幾何のセルフテストを実行し、結果をページ先頭に表示する |

### コマンド出力の使い方

座標はすべて相対（`~`）です。データパックの `data/<名前空間>/function/build.mcfunction` に置いて、
建てたい場所で `/function <名前空間>:build` を実行してください。原点は図面の左上ではなく、
半径で指定する形状では**中心**です（テキスト図面のヘッダーに、左上のセルの座標が出ます）。

## 完成イメージ

平面図と立面図だけだと、積み上がった姿が分かりません。「完成イメージ」タブで等角投影で見られます。

- **回す** … 90 度ずつ、4 方向から見られます
- **積み上げ** … 「ここまで積んだ状態」を表示します。途中まで建てて、残りを確認したいときに
- **大きさ** … 大きい建物で重いときは下げてください
- **PNG 保存** … 完成イメージを画像で保存します

3D ライブラリは使っていません（ビルド不要・依存なしを崩さないため）。キャンバスに立方体を
奥から手前の順で描いているだけです。カメラから見て手前 3 方向がすべて埋まっているブロックは、
どうやっても見えないので最初から描きません。

## 図面の読み方

形から作った図面の記号は次のとおりです。

| 記号 | 意味 |
| --- | --- |
| `#` | ブロック |
| `^` `>` `v` `<` | 階段ブロック。**矢印は上り方向**で、そのまま `facing` の値になる |
| `+` | 隅棟（寄棟屋根の角） |
| `|` | 柱 |
| `.` | 空 |

読み込んだ建築や、実際の建物のようにブロックの種類が多いものは、
多い順に `A-Z a-z 0-9` を割り当てて**凡例**を付けます。

画面上では、外側に面しているブロック（輪郭）だけ色を変えています。数える必要はありません。
どちらも同じブロックです。読み込んだ建築は、種別ではなく**素材そのものの色**で塗ります
（地図と同じ考え方で、明暗どちらのテーマでも同じ色になります）。

### 階段の向きについて

階段ブロックの `facing` は**上り方向と一致します**。`facing=east` の階段はモデルの高い側が
+X（東）にあるので、西から東へ上ることになります。切妻屋根なら、西側の斜面は棟に向かって
東へ上るので `facing=east`、東側の斜面は `facing=west` です。

## 仕組み

`index.html` の 1 ファイルだけで完結しています。ビルド不要、依存パッケージなし、オフラインで動作します。
設定ジェネレータ（[`../`](../README.md)）と同じ作り方です。

- **`state` が唯一の真実**。フォームは `state` を書き換えるだけ
- 生成は **state → グリッド の純粋関数**（`buildCylinder` / `buildSphere` / `buildCone` /
  `buildGable` / `buildHip` / `buildShed` / `buildSpiral` / `buildArch` / `buildBuilding`）。
  描画・テキスト・コマンド・材料表はすべてこのグリッドから作る

### グリッドとパレット

1 セルは**ブロックパレットの添字**（`Uint16Array`、0 は必ず空気）です。

```js
palette[i] = { id: "minecraft:oak_stairs", props: { facing: "east" }, kind: K.STAIR, dir: DIR.EAST }
```

向きの違うブロックは別のパレット項目になります。これはスケマティックの持ち方と同じなので、
読み込んだファイルもパラメトリック生成も同じ器に載り、材料表も同じ集計で出せます。
`gGet` / `gDir` は種別と向きを返す（パレットから引く）ので、形状ジェネレータ側は
パレットを意識せずに書けます。

### スケマティックの読み込み

NBT パーサーは依存なしで書いています。gzip は `DecompressionStream`、64bit は `BigInt`。
先頭 2 バイトが `1f 8b` でなければ非圧縮としてそのまま読みます。

- **Sponge**（`.schem`）は 1 ブロック 1 varint。v3 は `Schematic.Blocks` の下に入るので分岐して同じ処理へ
- **Litematica**（`.litematic`）は long のビットパック。ビット幅は `max(2, ceil(log2(パレット数)))` で、
  1 個の値が long の境界をまたぐことがあるため、またぐ場合は 2 本から組み立てます。
  領域が複数あるときは位置と大きさから全体を囲む箱を出して 1 つにまとめ、負の `Size` は原点をずらして正規化します

### 有名建築の作り方

`LANDMARKS` に、建物ごとの実寸（m）・既定スケール・部品の組み立てを持たせています。
部品は `pBox` / `pFrustum`（台形）/ `pPyramid` / `pColumn` / `pDome` / `pHipRoof` /
`pArcade`（開口付きの楕円リング）/ `pArchVoid`（くり抜き用の開口）で、
`assembleParts` が全体を囲む箱を作って `blitGrid` で置き、`carve` の指定は最後にくり抜きます。
屋根とドームとアーチは、形状ジェネレータをそのまま呼んでいます。

```js
taj_mahal: {
  real: { w: 95, d: 95, h: 73 }, scale: 1.5,
  parts: (c) => [ mid(pBox(c.st, "minecraft:quartz_bricks", c.m(95), c.m(6), c.m(95)), 0), ... ],
}
```

`c.m(メートル)` がブロック数への換算です。実寸を書いてから換算するので、
スケールを変えても各部の比率が崩れません。

### 形状の作り方

**円のラスタライズ**は `(dx/ax)² + (dz/az)² <= 1`。半軸 `ax` は、
奇数直径なら `r + 0.5`（中心がブロック、幅 `2r+1`）、偶数直径なら `r`（中心が 2×2 の境目、幅 `2r`）。
`r + 0.5` を使うのは、`r` のままだと上下左右の端が細くとがるためです。半径 5 なら、
よく知られている直径 11 の円と一致します。

**空洞化**は、内側の楕円を引き算するのではなく、**6 近傍による収縮（`erode`）との差**で出しています。
引き算だと曲率が急なところで殻に穴が開きますが、収縮の差なら厚みがどこでも一定になり、必ず閉じます。
`openBottom` / `openTop` は「範囲外を中身とみなす」指定で、ドームの底や円柱の上下に
蓋ができるのを防ぐために使います。円柱・球・ドーム・円錐はすべてこの 1 つの経路（`fillSolid`）です。

**円錐**だけは、層ごとの半径を**整数に丸めてから**円にしています。丸めずに半径を連続的に縮めると、
途中の層に 1 マス幅のとげが出ます。丸めると、どの層も普通の円になります
（同じ半径が 2 段続くことがありますが、それは実際に積む形と同じです）。
球はこの丸めをしていません。3 次元の距離で決まる形をそのまま出したほうが、
他の球ジェネレータの結果と一致するためです。

**アーチ**は、開口（通り抜けるほう）を半楕円で作り、それを厚みの分だけ**ふくらませた差**を輪にします。
楕円を 2 つ引き算するやり方だと頂部の厚みが一定にならず、輪が閉じないことがあります。

**寄棟屋根**は、四辺からの距離の最小値がその層の帯に入るセルを置きます。
X 側と Z 側の斜面が同時に当たるセルが隅棟、向かい合う斜面が出会うセルが大棟です。

## テスト

幾何の不変条件のテストがページ自体に入っています。ブラウザで `index.html?selftest=1` を開くと
結果が出ます。ヘッドレスでも実行できます。

```bash
# ローカル（このリポジトリの開発環境）
/opt/pw-browsers/chromium_headless_shell-*/chrome-linux/headless_shell \
  --disable-gpu --no-sandbox --virtual-time-budget=3000 \
  --dump-dom "file://$PWD/app/minecraft/index.html?selftest=1" | grep -o 'SELFTEST: .*failed'
```

見ているのは、たとえば次のようなことです。

- 完成イメージが、内部に埋まったブロックを描かない（3×3×3 なら 27 個のうち 19 個だけ）。
  どの向きでも数が変わらず、奥から手前の順に並び、積み上げの指定が効くこと
- 円が 4 回対称で、各行に穴が開いていない
- 中実の球のブロック数が `4/3πr³` とおおむね一致する
- 空洞の球の内側から外へ漏れない（殻が閉じている）
- 円錐の各層が、同じ半径の円ジェネレータの出力と一致する
- 切妻屋根が左右対称で、階段の向きが左右で逆になる
- 螺旋階段の隣り合う段が飛ばない（飛ぶ設定では警告が出て、推奨の段数が提示される）
- `.mcfunction` の行数がブロック数と一致する
- **4 形式（`.nbt` / `.schem` v2 / `.schem` v3 / `.litematic`）が完全に同じ図面になる**。
  3×3×3 の最小フィクスチャを埋め込んであり、ブロック状態と向きが残ることまで見る
- ビットパックの解除が、ビット幅 2 / 3 / 5 で long の境界をまたいでも正しい
- 材料表の合計がグリッドの総ブロック数と一致し、`facing` 違いが 1 行にまとまる
- 建物の壁が閉じていて、窓が壁を貫通せず、玄関が指定した面だけに開く
- **有名建築 11 件が、どれも実寸÷スケールと ±20% 以内に収まる**。部品の組み方を間違えると、
  まずここが外れる。あわせて、空中に浮かないこと・建物ごとに材料が違うこと・
  くり抜き（凱旋門の横断アーチ）が効いていること・外面モードで中身だけが消えることを見る

CI（`.github/workflows/pages.yml`）でも同じテストが走り、**1 件でも失敗するとデプロイされません。**

## 既知の制限

- 螺旋階段の各段は宙に浮いた階段ブロックです（マイクラでは支えが要らないのでそのまま置けます）。
  下を埋めたい場合は、図面の位置を見ながら手で足してください
- 図面は 1 ブロック単位で、平面図は上から見た 1 段ぶんです。
  ハーフブロックや上下反転の階段は、ブロック状態としては保持しますが図面上では区別しません
- 読み込んだファイルのタイルエンティティ（チェストの中身、看板の文字、スポナーの設定）は読みません。
  ブロックの配置と種類だけを扱います
- `.mcfunction` は `setblock` を 1 行ずつ出します。大きな形では行数が数万になります
- 「実際の建物」は寸法から外郭を起こすものです。写真や間取り画像からは起こせません
- 有名建築は**単純化した外形**です。装飾・曲面・内部の間取りは入っていません。
  収録していない建物は出せないので、その場合は寸法から起こすか、
  作られたものを配布元から読み込んでください
- 配布元として直接開けるのは GitHub だけです。CORS を返さないサイト（minecraft-schematics.com、
  PlanetMinecraft など）は、ダウンロードしてからドロップしてください
- 同梱サンプルの一覧は同一オリジンの `fetch` で読むため、`file://` で直接開いた場合は使えません
  （その場合はドロップを使ってください）。公開 URL 経由なら問題ありません
