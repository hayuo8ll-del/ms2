Claude Code 設定ジェネレータ.

答えるだけで CLAUDE.md / settings.json / フック / サブエージェント / スキル / .mcp.json を生成します

CLAUDE.md

毎セッション全文が読み込まれる常時コンテキスト。「これを消したら Claude はミスをするか？」に YES のものだけ書きます。 → ガイド 06

プロジェクト

コードを読めば分かることは書かない。ここは 1 行で十分です。

開発コマンド（Claude が推測できない最重要情報）

ここに入れたコマンドは、「権限」タブで許可ルールの候補として使えます。

コードスタイル（デフォルトと違う点だけ）

❌「コードを適切にフォーマットする」→ ⭕「インデントは半角スペース 2 つ」。検証できる粒度まで具体的に。

作業ルール

行頭に ! を付けると **IMPORTANT:** が付き、遵守率が上がります。

落とし穴・環境の癖

インポート先も起動時に読み込まれます。分割は整理のためで、コンテキスト削減にはなりません。

権限（.claude/settings.json）

モードが土台、その上に allow / ask / deny を重ねます。deny と ask は全モードで有効です。 → ガイド 07

権限モード

allow（確認なしで通す）
ask（常に確認する）
deny（常に拒否する）
その他

認証情報はここに書かないでください。settings.json は git にコミットされます。

フック

CLAUDE.md の指示が「お願い」なのに対し、フックは必ず発火します。ガードレールはここに置きます。 → ガイド 08

よく使う構成をそのまま追加できます:

サブエージェント

独自のコンテキスト・ツール権限を持つ隔離ワーカー。調査や大量のファイル読み込みを任せると、メインの会話には要約だけが返ります。 → ガイド 08-5

スキル

本文は使うときにだけ読み込まれるので、長い手順書を置いてもコンテキストをほとんど消費しません。/名前 で呼び出せます。 → ガイド 08-2

MCP サーバー

「別のツールからチャットにデータをコピーしている」と気づいたら、それが MCP を繋ぐサインです。.mcp.json はチーム共有（project スコープ）になります。 → ガイド 08-4

パススコープルール（.claude/rules/）

特定のファイルを扱うときだけ読み込まれるルール。CLAUDE.md が 200 行を超えたら、ここへ移すとコンテキストを節約できます。 → ガイド 06-6
